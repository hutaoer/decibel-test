## 分贝测试 H5 版（uni-app）交付

- 背景：微信小程序无法在浏览器运行（双线程架构依赖微信运行时），用户要求 H5 版本
- 产出：`decibel-h5/`（uni-app Vue3 + Vite，官方 uni-preset-vue#vite 模板），三页面 Demo
- 采集：getUserMedia + AnalyserNode 时域 RMS；**必须显式传 autoGainControl/noiseSuppression/echoCancellation 三个 false**，与小程序 audioMode:'recording' 同源坑
- 换算：dB SPL ≈ dBFS + 94（K=94 未校准估算），校准滑杆 ±15dB 存 localStorage
- 计算口径与 decibel-mp 同构：能量平均 Leq、峰值事件（≥85dB 持续 1s）、NIOSH 剂量；记录结构 id/startTime/leq/samples/peaks/k/tag
- 分享：navigator.share 降级剪贴板；海报用 DOM canvas 导出 PNG（浏览器专用，回编小程序需替换）
- H5 无 600s 录音上限；getUserMedia 要求 HTTPS/localhost；iOS 需用户手势中创建 AudioContext
- dev server 验证：npm run dev:h5 → localhost:5173 编译通过、页面 200
- 回编注意：utils/audio.js 与 utils/poster.js 是浏览器专用，mp-weixin 编译前需换回 RecorderManager/小程序 Canvas

## Bug 修复：小程序版分贝显示负值（-47.2 dB）

- 现象：真机测量 current -47.2、Leq -9.6、max 0.9、min -52.9；gauge 指针贴在最左
- 根因：`decibel-mp/utils/decibel.js` 的 `DEFAULT_K = 10`。K 是 dBFS→dB SPL 偏移量，满量程 0dBFS≈94dB SPL，正常量级 90 左右；K 小 84dB → 全部读数为负。H5 版一直用 94 所以正常
- 修复：DEFAULT_K=94 + K_MIN/K_MAX=74/114；storage 默认 94 且迁移旧数据 k<60 → 94；校准入口改为「输入差值」而非绝对值；低于量程显示「＜30」；PRD 4 处 K=10 同步更正
- 验证：dbFromRms(100,94)=43.7、dbFromRms(1000,94)=63.7、dbFromRms(3277,94)=74.0；迁移三态通过
- 经验：dBFS→SPL 偏移量绝不能用个位数；两端（小程序/H5）必须共用同一 K 口径
